# Контекст: расширения для S800 HT Dual

Ветка `S800`. Дата: 14.08.2026. Для того, кто продолжит работу.

Два расширения, которые нужны принтеру S800 HT Dual и которых нет в
апстриме Klipper: `named_probe` и `multiplex_heater`. Раньше они лежали в
репозитории конфигов `Config_printer/klipper-extras/` и ставились на
принтер симлинками вручную. Это было неправильно: код прошивки должен жить
в репозитории прошивки, а в конфигах — только `.cfg`. Перенесены сюда.

## Что за машина

S800 HT Dual — **не тулченджер**. Две головы постоянно стоят на каретке,
смена инструмента выполняется только сервоприводами, без движения по XY:

- `[servo TCHS]` — коромысло подъёма: одна голова вверх, другая вниз;
- `[servo VLVE]` — клапан, подводится под сопло поднятой головы и отсекает
  ооз.

Отсюда обе особенности, ради которых написаны расширения.

## named_probe

**Задача.** В штатном Klipper допускается ровно одна секция `[probe]`.
Команда `PROBE`, homing через `probe:z_virtual_endstop`, bed mesh и QGL
всегда идут через неё. На S800 обе головы одновременно на каретке, и для
измерения разницы высот нужен отдельный датчик касания на второй голове.

**Что делает.** Регистрирует секции `[named_probe NAME]` и команды
`PROBE_NAMED` / `QUERY_PROBE_NAMED` с mux-параметром `PROBE=`. Штатный
`PROBE` не перехватывает и `probe:z_virtual_endstop` не регистрирует, чтобы
не конфликтовать с основным датчиком.

**Где используется.** `[named_probe t1]` в `bed.cfg` профиля S800; макросы
`Zoffset` / `_GT1` в `tools.cfg` читают
`printer["named_probe t1"].last_z_result`.

**Состояние.** На машине секция и макросы сейчас закомментированы, значение
`t1_z_offset` задано вручную. Это осознанное решение, а не недоделка.

Подробности — [../named_probe.md](../named_probe.md).

## multiplex_heater

**Задача.** У S800 стол собран из 4 плит, а камера из 2 нагревателей, у
каждого свой пин и свой термистор. Без расширения в Fluidd / Mainsail /
KlipperScreen торчали бы 6 отдельных нагревателей вместо одного стола и
одной камеры.

**Что делает.** `[multiplex_heater heater_bed]` — публичный «фасад», за ним
несколько `[multiplex_heater_segment]`. Отображаемые температура и мощность
— среднее по активным сегментам, каждый сегмент греется своим PID по своему
термистору, `verify_heater` работает на каждом отдельно. Сегменты
регистрируются с префиксом `_`, поэтому в UI не видны.

Два `.py` нужны потому, что в Klipper имя секции = имя модуля.

**Дополнительно.** `SET_MULTIPLEX_HEATER HEATER=heater_bed TARGET=60
SEGMENTS=0,1` греет только часть плит. Маска сохраняется до следующей явной
установки.

**Где используется.** `heaters.cfg` профиля S800: 4 сегмента стола и 2
сегмента камеры.

Подробности — [../multiplex_heater.md](../multiplex_heater.md).

## Совместимость

Оба модуля написаны под Klipper `v0.13.0` (форк Z-Bolt, коммит `259decb0`).
`named_probe` завязан на внутренний API `probe.py`: `ProbeEndstopWrapper`,
`ProbeSessionHelper`, `ProbeParameterHelper`, `ProbeOffsetsHelper`,
`run_single_probe`. При обновлении апстрима это первое, что стоит
проверить — при несовпадении конструктора модуль упадёт на загрузке с
понятным traceback.

## Установка

Ничего делать не нужно: модули лежат в `klippy/extras/` и приезжают с
обновлением прошивки.

**Важно при первом обновлении принтера**, куда модули раньше клали руками:
неотслеживаемые файлы в `~/klipper/klippy/extras/` заблокируют `git pull`.
Перед обновлением их надо удалить.
