# Офлайн-стенд расширений Z-Bolt

Прогон логики без принтера. `harness.py` подменяет ровно тот кусок хоста
Klipper, который расширения реально дёргают: реактор, toolhead, gcode,
buttons, save_variables, probe, TMC-драйверы. Это не эмулятор Klipper —
только то, что нужно для проверки поведения.

## Запуск

```bash
cd test/zbolt
python3 test_toolchanger.py          # поведение: состояния, аварии, офсеты
python3 test_trajectory_parity.py    # траектории против старых макросов
python3 test_shipped_configs.py      # то же, но параметры берутся из конфигов
```

Каждый скрипт возвращает ненулевой код при провале, так что их можно
ставить в CI как есть.

| Файл | Что проверяет |
|------|---------------|
| `test_toolchanger.py` | Определение состояния при старте, матрица аварий и реакции на них, сервисный режим, офсеты и их перенос между головами, калибровка, фильтр дребезга, сторож реального времени |
| `test_trajectory_parity.py` | Что движение парковки и захвата совпадает **точка в точку** с раскрытием старых макросов каждой модели |
| `test_shipped_configs.py` | То же сравнение, но параметры читаются из `zbolt_toolchanger.cfg` реальных профилей — проверяет, что на машины уедут правильные числа |

## Зависимость от репозитория конфигов

`test_shipped_configs.py` читает профили принтеров из соседнего
репозитория `Config_printer`. По умолчанию ищет его рядом с этим
репозиторием; путь переопределяется:

```bash
TC_REPO=/путь/к/Config_printer python3 test_shipped_configs.py
```

Модули берутся из `klippy/extras/` этого репозитория; при необходимости
переопределяется через `TC_EXTRAS`.

## Зачем это нужно

Стенд не косметика: на нём поймано несколько дефектов, которые на живой
машине выглядели бы как редкие необъяснимые аварии — залипший флаг
прерывания после ручного касания головы, гонка стартовой детекции с
докладом MCU и сравнение признака «показания невалидны» с номером
инструмента T0 (`False == 0` в Python), из-за которого защита на самой
частой голове была фактически выключена.
